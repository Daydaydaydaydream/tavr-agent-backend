# RCVIPlan（Qt）开发规划

## 1. 项目完整路线与当前步骤

以下沿用此前讨论的“阶段 A：V1 本机联调 → 阶段 B：规则与协议扩展 → 阶段 C：知识或大模型”路线，将 Qt 的职责逐步展开。当前处于阶段 A 已验证、阶段 B 接口设计已完成、待实施。

| 步骤 | 阶段 / 状态 | Qt 设计与工作 | 完成标志 |
| --- | --- | --- | --- |
| 1 | A：V1 接入，已完成 | HTTP 发送软件状态，展示后端提示，用户点击进入取点页面；超时和旧响应失效 | 用户已确认 Qt 与 Backend 联调完成 |
| 2 | B：D0 接口设计，已完成设计 | 明确真实状态、事件、保存版本及动作入口，与 Backend 冻结 V2 契约 | D0 所有设计产物通过检查，先于业务代码开发 |
| 3 | B：Q1 状态实现，待开发 | Model 管理结果，Control 在主线程汇总一致快照；补齐分割生命周期 | 冷启动、运行、成功、失败均可正确查询 |
| 4 | B：Q2 规划一致性，待开发 | 取点变化使定位失效；当前内容版本与保存版本分离 | 操作回退和编辑后不会错误显示完成 |
| 5 | B：Q3 界面与协议接入，待开发 | 独立保存入口、V2 HTTP、原因展示、导航白名单；保留 V1 配置 | 引导跟随真实状态，动作不代替用户执行业务 |
| 6 | B：Q4 联调与交付，待执行 | Qt 测试、目标 Windows 构建、两端联调、兼容与回退 | 验收记录齐全 |
| 7 | C：知识 / 大模型接入，后续 | 展示解释和受支持问题的回答；Qt 继续持有真实状态和动作校验 | 阶段 B 稳定，知识来源、问题范围与回退方案先完成设计 |

正式瓣环确认、测量、报告等属于业务功能扩展，具体排期尚未约定；功能实现后才能增加对应状态。本轮不以取满三点替代瓣环确认，不以假体就绪替代测量完成。

日期：2026-10-14。本文为开发计划，接口基线 2.0.0 已输出，未修改业务代码。配套文档：[Backend 开发规划](backend-development-plan.md)，两端统一引用 [V2 接口设计](contracts/guide-v2-interface-design.md)。

## 2. 开发前置阶段 D0：先完成设计，再开始实现

本轮顺序固定为：业务语义确认 → 接口设计完成 → 契约冻结 → 两端实现 → 联调验收。Q1 和 B1 均不得在 D0 未完成时开始；不能先写状态类或接口，再由实现反推协议。

D0 设计交付已完成，采用 **2.0.0 设计基线**，不表示 V2 已实现或已运行验收。交付包括 [接口设计](contracts/guide-v2-interface-design.md)、[OpenAPI](contracts/guide-v2.openapi.yaml)、[决策表](contracts/guide-v2.decision-table.json)、[共享样例](../tests/fixtures/guide_v2/README.md) 与 [检查记录](contracts/validation-report.md)。

D0.1 业务语义、D0.2 状态字典、D0.3 HTTP 契约、D0.4 Qt 内部接口、D0.5 规则与导航、D0.6 样例均已定义；D0.7 统一版本为 2.0.0。下一步可按本设计进入 Q1 / B1。运行验收仍需实施后执行。

冻结之后任何字段、枚举、前置条件、错误码或动作语义变更，必须先更新契约和样例、记录兼容性影响，再改两端代码。V1 保持原行为。

## 3. 当前基线、目标与范围

本阶段目标是“已有规划功能的状态感知引导”：Qt 上报真实状态，后端返回与当前操作匹配的提示，用户通过明确点击进入已有界面。验收终点是能够解释等待、失败、操作回退、待保存和保存成功，而非仅证明 HTTP 通信正常。

用户已确认 V1 Qt / Backend 联调完成。本计划依据当前源码静态检查制定，未重新编译或运行 Qt。

| 项目 | 检查基线 | 当前能力 |
| --- | --- | --- |
| RCVIPlan | `b6949dc` | Qt 5、HTTP 客户端、超时和过期响应过滤、引导面板、取点页面导航 |
| Backend | `2d941e9` | FastAPI、严格请求校验、三个布尔值的确定性规则、无状态接口 |

Qt 的 `GuidanceState()` 当前只读取真实 CT 加载状态；瓣环确认和测量完成固定为 false。取点、分割和假体规划已存在，但未作为独立状态上报。`IsSentPlanReady()` 只检查点数与模型指针，不能直接代表当前规划几何有效或已保存。

历史状态文档中的 gRPC、事件订阅和旧缺陷清单不能直接当作当前需求。实施时以源码为准：同步取点、关闭保存处理和 QSaveFile 原子保存等已有实现应复用。

本期包括：状态快照、分割生命周期、取点和假体状态失效、独立保存入口、V2 规则、Qt 展示及导航、兼容和联调。

本期不新增：测量工具、正式瓣环确认、报告导出、中心线业务扩展、LLM / RAG、数据库、gRPC、事件补发、远程部署、进程内切换病例。继续采用一个进程处理一个病例、全量 HTTP 快照。

已确定：分割不新增硬前置，通过独立 alerts 提示；新增“保存定位结果”入口；只保存现有 points / rotation_matrix，明确不含假体规格；点位改变使定位失效；异步假体增加 running / failed 状态。有后台任务时正常关闭需等待任务结束。完整决策依据见正式接口设计第 2 节。

## 4. 当前这一步的 Qt 设计（已完成）

详细状态类型、方法签名、线程规则和保存时序见 [接口设计第 6–10 节](contracts/guide-v2-interface-design.md)。Model 持有结果，Control 在主线程汇总 WorkflowSnapshot，AgentHttpClient 只处理协议，View 展示主建议和独立分割告警。

真实动作入口已映射到 page_segment / pb_autoSeg、page_selectPoint / pb_pointPick、page_navigation / pb_sentSetting，以及待新增的 pb_savePlan。导航不触发业务操作。假体异步结果按任务代次及点位版本过滤；所有 GUI / actor 操作转至主线程。

保存范围固定为取点及最终矩阵，采用同步原子提交；独立保存和关闭保存复用同一方法。规格参数、显示材质与透明度不属于持久化版本；界面明确不含假体规格。

## 5. Qt 开发工作包

### Q1：统一状态与主线程更新（依赖 D0 已冻结）

建议新增 `inc/agent/WorkflowState.h`、`src/Agent/WorkflowState.cpp`，提供轻量值类型、转换校验及版本管理；由 Control 持有状态汇总，不让 View、网络类和 Model 各维护一份完成标志。

- Model 持有操作结果与分割任务生命周期；通过明确信号将结果交给 Control，Control 在主线程更新快照。
- 首次请求主动查询已同步完成的 CT 加载结果，不能只依赖构造期信号。
- CT 失败原因单独记录，避免用分割的 `LastError()` 解释 CT 失败。
- 分割开始、缓存命中、成功、失败均有终态出口；新尝试开始和成功时清除旧错误。当前源码缓存命中及成功路径未清理 `LastError()`，本包补齐。
- 单次分割任务在运行时禁止重复启动；Qt 后台任务持有有效生命周期，窗口关闭不能留下捕获已销毁对象的回调。本版固定为运行期间禁止正常关闭并明确提示，取消任务不在本期范围。
- 分割结果是否可用与缓存提交是否成功分开维护；不要仅凭 `IsSegmentValid()` 推断任务成功。

涉及文件：`RCVIPlanModel.h/.cpp`、`RCVIPlanControl.h/.cpp`、新增 WorkflowState。

完成标准：冷启动、缓存命中、配置失败、处理失败、结果保存失败和成功均可得到唯一、可查询、无过期错误的状态。

### Q2：取点、假体和保存的版本一致性（依赖 Q1）

- 取点/删点以实际成功修改结果为准更新点数和版本；检查失败时不得更新标签或误增版本。
- 修改点位使既有假体定位失效；从 3 点删到 2 点再补到 3 点，不能自动把旧定位恢复为 ready。
- 假体创建、`ImportVirtualSent()`、`ChangeVirtualSent()`、`UpdateSentModel()`、参数/材质切换、复位等路径逐个核查。只有当前输入的几何计算和应用成功才置 ready。
- 纯页面、窗宽窗位、透明度等未纳入保存内容的变化不增加 `plan_revision`；实际保存内容变化必须增加。一次逻辑修改统一提交版本，避免内部重复调用造成多次递增。
- 保存时冻结待保存版本与数据，只有 `QSaveFile::commit()` 成功才更新 `saved_plan_revision`；写入失败保留上一成功版本。
- 本版同步保存且不进入嵌套事件循环，禁止重入编辑；不承诺 HTTP 可观察到每个中间 running 状态。
- 保持 `sent_plan.json` 原有 points / rotation_matrix 格式；本版不保存假体规格，相关提示必须说明范围。完整假体恢复格式另立设计。

涉及文件：`RCVIPlanControl.h/.cpp`、`RCVIPlanModel.cpp`、`VirtualSentSettingView` 的事件接线、WorkflowState。

完成标准：删点/补点/重新定位/参数修改后均不会错误显示“当前取点与定位矩阵已保存（不含假体规格）”，失败保存不会覆盖已保存版本。

### Q3：独立保存与 V2 界面接入（依赖 Q2、B2）

- 增加普通业务“保存定位结果”入口，由用户点击调用共享保存流程；关闭保存复用同一流程及错误处理。
- 扩展 `AgentHttpClient`：协议选择、V2 序列化、严格响应检查、关联 ID 和版本核对；保留现有 3 秒总超时、64 KiB 限制、无代理和本机地址约束。
- 保留 generation 控制；即使两个请求的状态版本相同，也只接收最新请求。更新状态立即废弃旧响应和旧按钮，再合并同一轮同步事件发送最终快照。
- 成功及失败响应都核对请求是否仍有效；协议不匹配、未知动作和无效响应均不执行导航。
- `RCVIPlanView` 展示提示与严重程度；用户界面不堆砌 reason_code、请求 ID 等调试信息。
- 建立 V2 动作映射和 `supported_actions`，核实分割/设置入口，不依赖显示文本匹配。
- 控制层执行业务前置检查；引导不可用时已有业务功能仍可使用。

涉及文件：`AgentHttpClient.h/.cpp`、`RCVIPlanControl.h/.cpp`、`RCVIPlanView.h/.cpp`、必要的 `.ui`、`CMakeLists.txt`。

完成标准：可在 V1 / V2 间显式切换，V2 能跟随实际事件更新，并且导航不会执行业务操作。

### Q4：验证和文档（依赖 Q1–Q3）

- 状态转换、版本失效、响应解析使用 Qt Test 或轻量测试目标，尽量与 VTK 和真实分割引擎隔离。
- HTTP 使用本机可控测试服务模拟延迟、失败、乱序、错误字段和版本不匹配。
- 在现有 Windows / Qt 5 / VTK / RCVICommon 环境完整编译，再运行真实软件联调。
- 更新 `docs/http-guidance-integration.md`、状态来源表、配置说明及实际验收记录；历史文档加清晰的适用版本说明。

## 6. Qt 实施顺序与交付

1. 完成 D0，冻结 HTTP 契约及本地信号/方法契约。
2. Q1 统一状态，再完成 Q2 失效和保存版本逻辑。
3. 对照已冻结样例开发 Q3 客户端；后端 B2 就绪后开始真实联调。
4. 完成 Q4：自动验证及目标 Windows 编译运行。
5. 新 Backend 先部署，Qt 再切换 V2，保留显式 V1 回退。

测试客户端和本地假服务可以在契约冻结后使用，不必等待后端全部实现。每一步单独记录提交号、验证结果和未执行项。保存文件格式若改变，必须另外验证旧版读取；切回 V1 HTTP 并不会回退文件格式。

## 7. Qt 与联合验收

| 编号 | 场景 | 必须满足 |
| --- | --- | --- |
| A01 | 冷启动，有效 / 无效 CT | 首次快照准确；无效 CT 无不可执行导入按钮 |
| A02 | 0、1、2、3 个点 | 提示与真实计数一致；第 4 次取点不越界、不误增版本 |
| A03 | 创建假体后删点再补点 | 旧定位保持失效，重新定位成功后才 ready |
| A04 | 分割缓存命中 | 无需等待后台任务也能得到成功状态，清除旧错误 |
| A05 | 分割运行期间重复触发 | 不创建第二个任务；状态保持准确 |
| A06 | 配置错误、引擎失败、空结果 | 分别映射稳定错误码；不发布成功 |
| A07 | 分割结果可用但缓存保存失败 | 操作失败与结果可用同时正确表达 |
| A08 | 分割运行时关闭 | 无对象销毁后的后台访问；拒绝正常关闭并提示等待任务完成 |
| A09 | 独立保存成功 / 磁盘写入失败 | 仅实际提交成功更新保存版本；失败允许重试 |
| A10 | 保存后移动、重新取点或修改持久化参数 | 当前内容重新变成未保存 |
| A11 | 仅切页、调窗宽窗位、调显示透明度 | 不错误标记规划内容修改 |
| A12 | 状态改变后旧 HTTP 响应到达 | 成功、失败响应都不能覆盖当前提示 |
| A13 | 同状态连续刷新、响应乱序 | 只使用最新请求，关联 ID 与状态版本均正确 |
| A14 | 网络断开、超时、422、500、非 JSON、超大响应 | 可理解的错误，无导航，原业务功能可用 |
| A15 | 未知动作、缺少字段、错协议版本 | 拒绝执行；不解析中文文案作为控制逻辑 |
| A16 | 客户端不支持所需导航 | 后端返回 null，Qt 仍显示提示 |
| A17 | 用户点击导航 | 只导航或聚焦；不自动分割、取点、保存 |
| A18 | 关闭保存失败，用户取消退出 | 窗口恢复可用，引导可继续请求 |
| A19 | 新 Backend + 旧 Qt | V1 行为与已验证版本一致 |
| A20 | V2 Qt + 仅 V1 Backend | 明确版本不匹配；显式切回 V1 后可运行 |
| A21 | 非法枚举、布尔字符串、超界点数、矛盾版本 | V2 返回稳定 422，不回显原始输入 |
| A22 | 当前版本保存成功且仍有效 | 仅显示“当前取点与定位矩阵已保存（不含假体规格）”，不声称测量或完整流程完成 |

每条记录至少包含：两端提交号、环境、输入/操作、预期、实际、通过/失败、必要截图或日志。未运行的场景标为未执行，不能用静态检查代替。

## 8. 后续阶段 C 的 Qt 设计边界

阶段 B 验收后再设计解释或问答界面、取消请求、超时与失败展示。Qt 继续提供状态快照并校验动作；知识来源标识和模型响应契约须先与 Backend 设计完成。不得提前为尚未实现的测量和报告功能发布完成事件。
